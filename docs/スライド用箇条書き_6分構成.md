# 6分紹介スライド用 箇条書き(Memory Bank & Model Armor)

想定: 全8枚 / 1枚あたり約45秒。話す順序どおりに記載。

## Slide 1: タイトル & 今日のメッセージ(30秒)
- タイトル例: 「エージェントを"賢く"して"守る" — Memory Bank と Model Armor」
- ワンメッセージ: 本番運用のエージェントには「長期記憶」と「入出力ガードレール」の両方が必要
- Agent Platform(旧 Vertex AI Agent Engine)の構成要素として2つを紹介、と位置づけを一言

## Slide 2: 背景 — エージェント運用の2大課題(45秒)
- 課題①: LLM はステートレス。セッションが変わるとユーザーの好みや過去の文脈を忘れる
- 全履歴をプロンプトに詰めるとトークン肥大・コスト増・精度低下
- 課題②: プロンプト インジェクション / ジェイルブレイク / PII 漏えいなど、入出力起点のリスク
- → 課題①に Memory Bank、課題②に Model Armor

## Slide 3: Memory Bank とは(45秒)
- 会話から長期記憶を LLM で自動生成・管理するフルマネージド サービス(Agent Platform の一部)
- セッション横断でユーザーごとの「事実(fact)」を保持 → パーソナライズと会話の継続性
- 記憶はスコープ(ユーザーID × エージェント)で分離 → マルチテナントでも安全
- Google 研究の Reflective Memory Management に基づく設計

## Slide 4: Memory Bank の仕組みと主要機能(60秒)
- 流れ: Session に会話イベント蓄積 → GenerateMemories で抽出 → RetrieveMemories で取得しプロンプトへ
- 抽出: 会話ログの丸ごと保存ではなく「意味のある情報」だけを抽出
- 統合: 新情報を既存記憶と突合し、矛盾解消・重複排除しながら記憶が進化
- 非同期生成: バックグラウンド処理なので応答レイテンシに影響なし
- 取得: 類似性検索で「今の会話に関係する記憶」だけを注入 → トークン節約
- 運用機能: TTL(自動失効)、リビジョン履歴、IAM Conditions、CMEK / VPC-SC 対応
- ADK なら組み込みサービスでほぼ設定だけで利用可能(他フレームワークは API ラップ)

## Slide 5: Memory Bank ユースケース & RAG との違い(30秒)
- 例: 過去の問い合わせや好みを覚えているサポート エージェント / 調査結果を蓄積するリサーチ エージェント
- RAG = 静的な外部ナレッジ参照、Memory Bank = 会話から動的に進化するユーザー文脈(補完関係)

## Slide 6: Model Armor とは(45秒)
- LLM の「プロンプトとレスポンス」を双方向でスクリーニングするマネージド ガードレール サービス
- モデル・クラウド非依存: Gemini 以外や他クラウド / オンプレのアプリにも REST API で適用可
- 4つのフィルタ: ①責任ある AI 安全カテゴリ(ヘイト等4種+CSAM常時ON) ②プロンプト インジェクション/ジェイルブレイク検出 ③Sensitive Data Protection(PII 検出・匿名化) ④悪意ある URL 検出
- 日本語対応(9言語でテスト済み)、PDF / Office ファイルの検査も可能

## Slide 7: Model Armor の運用設計(60秒)
- テンプレート: アプリごとにフィルタ×信頼度しきい値(高/中以上/低以上)を定義
- 適用タイプ: まず「検査のみ」+ Cloud Logging で影響を観測 → 「検査とブロック」へ段階移行
- フロア設定: 組織/フォルダ/プロジェクト単位で全社の最低保護基準を強制(個別の柔軟性と全社統制の2層)
- 差し込み場所が豊富: アプリから直接 API / Agent Gateway / Vertex AI(Gemini API) / Apigee / GKE Inference Gateway・LB
- 違反は Security Command Center に Findings として集約 → 監視・アラート・修復フローへ

## Slide 8: 2つを組み合わせる & まとめ(45秒)
- 接点: 長期記憶は汚染されるとセッションを超えて影響が残る(メモリ ポイズニング)
- 公式推奨: Memory Bank に出入りするプロンプトを Model Armor で検査
- 推奨アーキテクチャ: 入口で Model Armor 検査 → クリーンな会話だけを記憶化 → 出口でも検査 → フロア設定+SCC で統制
- まとめ: Memory Bank で「賢く」、Model Armor で「安全に」。両輪でエージェントを本番品質へ
- Next Step: ADK クイックスタート(Memory Bank)/ 「検査のみ」モードでの Model Armor 試験導入

## 想定 Q&A メモ
- Q: Memory Bank の記憶はどこに保存される? → フルマネージド ストアに永続化。ML 処理は構成したリージョン内。CMEK / VPC-SC / データ所在地に対応
- Q: 記憶が間違っていたら? → 統合時に矛盾解消される+リビジョンで変化を追跡可能+TTL で自動失効も設定可
- Q: Model Armor のレイテンシ/コストは? → 検査はトークン数課金。フィルタごとにトークン上限(多くは1万、SDPは13万)があり超過分はスキップされる点に注意
- Q: Gemini 以外のモデルでも使える? → Model Armor はモデル非依存。OpenAI / Anthropic / セルフホストモデルの前段にも配置可能
